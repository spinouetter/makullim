# 요청 #0092 — Finale 이미지 저장 시 "이미지 생성 중" 토스트

상태: 완료 <!-- 대기 / 진행 중 / 완료 / 보류 -->

---

## 요청 (작성: Spinouetter, 대화로 요청)

Finale 보드 이미지 저장(PNG/JPG)이 가끔 오래 걸린다. 어느 정도 걸리는지 체감하고 싶으니, 저장 버튼을 누르면 **실제 다운로드가 시작되기 전까지 "이미지 생성 중" 토스트**를 띄워줘.

---

## 정리 (작성: Claude)

- Finale 보드의 PNG/JPG 저장은 `exportRaster()` → `rasterize()`에서 **사진 60여 장을 data URI로 임베드(inlinePhotos) 후 2배 스케일 canvas 래스터화**를 하므로, 사진이 많은 보드는 생성에 1초 이상 걸릴 수 있다(그동안 아무 피드백 없음).
- 저장 버튼을 누른 순간부터 **다운로드가 트리거되기 직전까지** "이미지 생성 중…" 토스트를 표시해 체감 시간을 알 수 있게 한다. (PDF 저장은 이미 버튼 라벨을 "PDF 생성 중…"으로 바꾸므로 대상 아님.)

## 할 일 (작성: Claude)
- [x] `showToast(msg, duration)` 확장(app.js): `duration<=0`이면 자동 제거하지 않고 토스트 요소를 반환한다(기존 `showToast(msg)` 호출은 100% 호환 — 미지정 시 2500ms).
- [x] `exportRaster(type,ext,quality)`(finale.js, PNG·JPG 저장 공통 지점)를 `try/finally`로 감싸: 시작 시 `showToast("이미지 생성 중…", 0)`으로 지속 토스트 표시, `finally`에서 다운로드 직전 `toast.remove()`(실패해도 반드시 제거).
- [x] 캐시버스터 app.js v212·finale.js v80.
- [x] 헤드리스 검증: JPG 저장 클릭 → 토스트 41ms 등장 → 다운로드 시점 1176ms 제거(생성 ~1135ms) 확인(woojin 보드).

## 결정 사항 (작성: Claude)
- 진행 표시는 별도 스피너 없이 기존 토스트를 재사용 — 최소 변경, 하단 중앙 토스트로 방해 없이 표시.
- 제거 시점을 `triggerDownload` 직후(= finally)로 잡아 "생성 시작 → 다운로드"의 실제 소요를 그대로 반영한다.
- 사진 임베드가 병목의 실체 — 필요하면 후속으로 임베드 캐싱/병렬화로 생성 시간 자체를 단축할 수 있다(이번 범위 밖).
